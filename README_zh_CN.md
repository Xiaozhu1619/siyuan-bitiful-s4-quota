# 缤纷云 S4 用量看板

思源笔记插件。一键查看缤纷云 S4 的免费额度消耗 —— **API 请求数 / 出口流量 / 存储容量**，进度条直观显示占比。

> 适用于用**缤纷云 S4** 做同步后端的用户（思源 设置 → 关于 → 同步 → S3）。

## 界面

点击顶栏的云朵图标打开面板：

```

my-notes-bucket

今日使用  1,204 次请求 · 86.4 MB
占每日限额：请求 12.0% · 流量 1.7%

API 请求数                              4.20%
[████─────────────────────────]
4,200 次 / 10 万次              剩余 95,800 次

出口流量                                6.80%
[███████──────────────────────]
680.0 MB / 10.0 GB               剩余 9.34 GB

存储容量                                1.05%
[█────────────────────────────]
537.4 MiB / 50.0 GiB             剩余 49.48 GiB
```

- 打开面板**不会联网**，显示的是上一次的数据；点「**立即更新**」才拉取最新
- 点击面板以外的**空白处会自动收起**
- 进度条颜色：不到 80% 蓝色，≥80% 黄色，≥100% 红色

## 手机端

**支持移动端**，但入口位置与桌面不同：

- 桌面上是顶栏右侧的云朵图标；
- 手机上没有独立的顶栏图标位，入口在顶栏的**插件菜单**里，显示为「缤纷云 S4 用量」菜单项。

面板在窄屏（≤600px）下会自动切换成从**底部升起**的抽屉样式，按钮加大到适合手指点按的尺寸。
若在手机上找不到入口，请到 设置 → 插件 中确认本插件已启用。

## 免费额度（缤纷云官方口径）

| 计费项 | 免费额度 | 每月重置 | 每日上限 |
|---|---|---|---|
| API 请求数 | 100,000 次 / 月 | ✅ 重置 | 10,000 次 |
| 出口流量 | 10 GB / 月 | ✅ 重置 | 5 GB |
| 存储容量 | 50 GiB | ❌ **不重置** | — |

注意：免费额度按**账户**汇总，不是按桶。官方计费说明举例：账户下 3 个桶，当月请求数为各桶相加。
因此本插件支持填写**多个桶**并合并统计，这样显示的占比才等于真实的额度占用。

## 安装

1. 把 `siyuan-bitiful-s4-quota` 整个文件夹复制到工作区：
   `{工作空间}/data/plugins/siyuan-bitiful-s4-quota/`
2. 重启思源（或 设置 → 集市 → 已下载 → 刷新）
3. 在「已下载」中**启用**本插件
4. 点顶栏云朵图标 → 「设置」→ 填入 API Token 与桶名 → 点「立即更新」

不需要 Node、pnpm，也不用任何编译步骤。

## 配置

| 项 | 说明 |
|---|---|
| **API Token** | 到 https://console.bitiful.com/apiToken 获取 |
| **桶名称** | 例如 `my-notes-bucket`；有多个桶就都填上，用逗号分隔，会合并统计 |
| **自动刷新间隔** | 默认 300 秒 |
| **启用自动刷新** | 关闭后只有点「立即更新」才会拉数据 |

桶名在哪看：思源 设置 → 关于 → 同步 → S3 → **Bucket**。

> 建议保留自动刷新：缤纷云日志只保留最近 3 天左右，长期不拉取会导致中间数据永久缺失、月度统计不完整。

## 安全性

**对你的笔记零影响。** 插件只调用缤纷云的两个**只读**接口（读容量、读日志），
不调用任何思源笔记 / 块 / 文档 / 文件相关接口，不会读写或修改你的任何内容。

**Token 请注意：** API Token 会**明文保存**在插件自己的私有目录
`{工作空间}/data/storage/petal/siyuan-bitiful-s4-quota/config.json`。
如果你开启了思源同步，该目录可能被一并同步到云端。建议使用**专用 Token**。

## 已知限制

- **流量为估算值**：按日志中各次响应的字节数累计，与缤纷云账单口径（按小时取整汇总）可能存在小幅偏差，当作趋势参考即可。
- 第一次更新会回填缤纷云日志窗口内的历史记录，因此统计起点可能早于插件安装时间。
- 若更新间隔过长、且期间请求量很大，可能漏计。建议间隔不超过 300 秒。
